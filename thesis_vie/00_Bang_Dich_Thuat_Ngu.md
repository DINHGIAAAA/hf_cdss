# BẢNG DỊCH THUẬT NGỮ (Anh → Việt)

Bảng này dịch các thuật ngữ thường gặp trong luận văn. Cột **Giải thích ngắn** giúp hiểu khái niệm mà không cần đọc định nghĩa kỹ thuật dài.

## A. Phần mở đầu / cấu trúc luận văn

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Acknowledgments | Lời cảm ơn | Cảm ơn người đã hỗ trợ |
| Declaration | Lời cam đoan | Cam kết tính trung thực của luận văn |
| Abstract | Tóm lược / Tóm tắt | Tóm tắt ngắn toàn bộ nghiên cứu |
| List of Abbreviations | Danh sách từ viết tắt | Giải thích các chữ viết tắt |
| References | Tài liệu tham khảo | Danh mục nguồn trích dẫn |
| Appendix | Phụ lục | Hình, sơ đồ bổ sung |
| Thesis | Luận văn | Công trình tốt nghiệp |
| Chapter | Chương | Phần nội dung chính |

## B. Lâm sàng – suy tim và thuốc

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Heart Failure (HF) | Suy tim | Tim không bơm máu đủ nhu cầu cơ thể |
| HFrEF | Suy tim phân suất tống máu giảm | Thường LVEF ≤ 40% |
| HFpEF | Suy tim phân suất tống máu bảo tồn | LVEF thường ≥ 50% |
| HFmrEF | Suy tim phân suất tống máu giảm nhẹ | Vùng LVEF trung gian |
| LVEF / Ejection Fraction (EF) | Phân suất tống máu thất trái | % máu thất trái bơm ra mỗi nhịp |
| GDMT | Điều trị nội khoa theo hướng dẫn | Bộ thuốc nền tảng đã được chứng minh |
| Guideline | Hướng dẫn điều trị | Khuyến cáo của hội chuyên môn (ESC, AHA…) |
| ESC | Hội Tim mạch Châu Âu | Tổ chức ban hành guideline châu Âu |
| AHA/ACC/HFSA | Hội Tim mạch Hoa Kỳ / ACC / HFSA | Tổ chức ban hành guideline Mỹ |
| ACEi | Thuốc ức chế men chuyển | Giãn mạch, bảo vệ tim–thận |
| ARB | Thuốc chẹn thụ thể angiotensin | Tương tự nhóm RAAS, thay thế ACEi khi cần |
| ARNI | Thuốc ức chế thụ thể–neprilysin | Ví dụ sacubitril/valsartan (Entresto) |
| Beta blocker | Thuốc chẹn beta | Giảm nhịp tim, cải thiện tiên lượng HFrEF |
| MRA | Thuốc đối kháng thụ thể mineralocorticoid | Ví dụ spironolactone; cần theo dõi K+ và thận |
| SGLT2 inhibitor (SGLT2i) | Thuốc ức chế SGLT2 | Có lợi trong suy tim, kể cả không đái tháo đường |
| RAAS | Hệ Renin–Angiotensin–Aldosterone | Đường hormone mà nhiều thuốc suy tim nhắm tới |
| Washout | Khoảng nghỉ thuốc | Ví dụ nghỉ ACEi trước khi dùng ARNI |
| Contraindication | Chống chỉ định | Không được dùng vì nguy hiểm |
| Indication | Chỉ định | Trường hợp được khuyến cáo dùng |
| Titration / Uptitration | Chuẩn liều / tăng liều dần | Tăng liều theo lịch và độ dung nạp |
| Starting dose | Liều khởi đầu | Liều bắt đầu điều trị |
| Target dose | Liều đích | Liều mục tiêu theo guideline/nhãn thuốc |
| Drug–drug interaction | Tương tác thuốc | Hai thuốc dùng cùng nhau gây nguy cơ |
| Polypharmacy | Đa thuốc | Dùng nhiều thuốc cùng lúc |
| Hyperkalemia | Tăng kali máu | Kali máu cao (nguy hiểm với MRA) |
| Hypotension | Hạ huyết áp | Huyết áp thấp |
| Bradycardia | Nhịp chậm | Nhịp tim chậm |
| eGFR | Độ lọc cầu thận ước tính | Đánh giá chức năng thận |
| Potassium (K+) | Kali máu | Điện giải cần theo dõi với một số thuốc |
| CKD | Bệnh thận mạn | Thận suy kéo dài, ảnh hưởng chỉnh liều |
| Phenotype | Kiểu hình lâm sàng | Phân nhóm suy tim (HFrEF/HFpEF…) |
| Comorbidity | Bệnh đồng mắc | Bệnh kèm theo |
| Vignette | Ca lâm sàng mẫu | Tình huống bệnh nhân dùng để đánh giá hệ thống |
| Cardiologist | Bác sĩ tim mạch | Người đánh giá/khuyến cáo chuyên sâu |
| Prescribing | Kê đơn | Quyết định cho thuốc |
| Monitoring | Theo dõi | Kiểm tra xét nghiệm, triệu chứng sau dùng thuốc |
| FDA / DailyMed / SPL | FDA / DailyMed / nhãn thuốc cấu trúc | Nguồn nhãn thuốc chính thức (Mỹ), dạng XML |

## C. Hệ thống hỗ trợ quyết định lâm sàng (CDSS)

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Clinical Decision Support System (CDSS) | Hệ hỗ trợ quyết định lâm sàng | Phần mềm giúp bác sĩ quyết định an toàn hơn |
| Recommendation | Khuyến nghị | Gợi ý điều trị có cấu trúc |
| Alert | Cảnh báo | Thông báo rủi ro / chống chỉ định |
| Hard block / hard constraint | Chặn cứng / ràng buộc cứng | Không được vượt qua (tránh tuyệt đối) |
| Soft constraint / caution | Ràng buộc mềm / thận trọng | Cảnh báo, vẫn cần phán đoán bác sĩ |
| Alert fatigue | Mệt mỏi vì cảnh báo | Quá nhiều cảnh báo → bác sĩ bỏ qua |
| Fail-closed | Thiết kế “đóng khi thiếu dữ liệu an toàn” | Thiếu lab quan trọng thì hỏi lại, không đoán |
| Human-in-the-loop (HITL) | Con người trong vòng quyết định | Bác sĩ vẫn quyết định cuối |
| Audit / Audit trail | Kiểm toán / nhật ký kiểm toán | Lưu lại ai làm gì, hệ thống trả gì |
| Governance | Quản trị tri thức/quy tắc | Duyệt, sửa, phê duyệt, ngưng quy tắc |
| Draft / Approved / Retired | Nháp / Đã duyệt / Ngưng dùng | Vòng đời quy tắc trong catalog |
| Clinical lead | Đầu mối lâm sàng | Người được quyền duyệt quy tắc |
| Plain-language summary | Tóm tắt ngôn ngữ dễ hiểu | Nhãn tiếng Việt/Anh trên thẻ khuyến nghị |

## D. Trí tuệ nhân tạo và truy xuất tri thức

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Large Language Model (LLM) | Mô hình ngôn ngữ lớn | AI đọc/viết văn bản (vd. Qwen) |
| Hallucination | Ảo giác / bịa thông tin | Model nói sai nhưng nghe có vẻ đúng |
| Prompt | Lời nhắc / câu lệnh cho model | Văn bản gửi vào LLM |
| Embedding | Vector nhúng | Biểu diễn số của văn bản để so độ giống nghĩa |
| Dense retrieval | Truy xuất dày (theo nghĩa) | Tìm đoạn văn gần nghĩa với câu hỏi |
| Sparse retrieval / BM25 | Truy xuất thưa / BM25 | Tìm theo từ khóa khớp chữ |
| Retrieval-Augmented Generation (RAG) | Sinh văn bản tăng cường bằng truy xuất | LLM trả lời dựa trên đoạn nguồn đã tìm |
| GraphRAG | RAG kết hợp đồ thị tri thức | Vừa tìm đoạn văn vừa đi theo quan hệ đồ thị |
| Knowledge Graph (KG) | Đồ thị tri thức | Mạng thực thể + quan hệ (thuốc–tương tác–bệnh…) |
| Node / Entity | Nút / Thực thể | Đối tượng trong đồ thị (thuốc, bệnh…) |
| Edge / Relationship | Cạnh / Quan hệ | Liên kết giữa thực thể |
| HyDE | HyDE (tài liệu giả định) | Sinh đoạn trả lời giả rồi dùng để tìm kiếm tốt hơn |
| Reciprocal Rank Fusion (RRF) | Hợp nhất xếp hạng nghịch đảo | Gộp kết quả từ nhiều bộ tìm kiếm |
| Reranking | Xếp hạng lại | Sắp xếp lại ứng viên top sau khi gộp |
| Chunk / Chunking | Đoạn / Cắt đoạn | Chia văn bản dài thành đoạn tìm kiếm được |
| Overlap | Chồng lấn | Đoạn sau giữ vài câu của đoạn trước |
| Vector store (ChromaDB) | Kho vector | Lưu embedding để tìm gần nghĩa |
| Neo4j | Neo4j (CSDL đồ thị) | Lưu và truy vấn quan hệ nhiều bước |
| Deterministic rules | Quy tắc tất định | Cùng input → cùng kết quả, kiểm chứng được |
| Verification agent | Tác tử kiểm chứng | Kiểm tra khuyến nghị vs an toàn/bằng chứng |
| Citation / Evidence | Trích dẫn / Bằng chứng | Đoạn nguồn hỗ trợ cho khuyến nghị |
| Provenance | Nguồn gốc / truy xuất nguồn | Biết quy tắc/bằng chứng lấy từ đâu |
| Named Entity Recognition (NER) | Nhận diện thực thể có tên | Tự tìm tên thuốc, bệnh trong câu |
| Lexicon | Từ điển thuật ngữ | Danh sách tên thuốc/từ đồng nghĩa |
| Negation detection | Phát hiện phủ định | “không dùng ACEi” ≠ “đang dùng ACEi” |
| Regex | Biểu thức chính quy | Mẫu bắt số liệu (EF, eGFR, K+) trong chat |
| Hybrid intake | Tiếp nhận hồ sơ lai | Regex + lexicon + LLM khi cần |
| Schema / JSON Schema / Pydantic | Lược đồ dữ liệu | Ép output LLM đúng cấu trúc |
| Idempotency | Tính lặp an toàn | Chạy lại không làm hỏng / không tốn lại chi phí thừa |
| Checkpoint | Điểm kiểm soát pipeline | Tiếp tục từ bước đã xong |

## E. Kiến trúc phần mềm và triển khai

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Architecture | Kiến trúc | Cách các phần hệ thống được tổ chức |
| Three-tier architecture | Kiến trúc 3 tầng | Giao diện – logic – dữ liệu |
| Presentation / Application / Data layer | Tầng trình bày / ứng dụng / dữ liệu | UI / backend / CSDL |
| Modular monolith | Đơn khối module hóa | Một backend, nhiều module rõ ranh giới |
| Microservice | Vi dịch vụ | Tách nhiều dịch vụ độc lập (không dùng chính ở đây) |
| Offline plane / Online plane | Mặt phẳng offline / online | Xây tri thức trước vs suy luận lúc chat |
| Pipeline / Ingestion | Đường ống / Nạp dữ liệu | Quy trình tự động lấy nhãn thuốc → quy tắc |
| Acquisition | Thu thập nguồn | Tải XML/PDF từ DailyMed, guideline |
| Section filter | Bộ lọc mục | Giữ mục lâm sàng, bỏ mục đóng gói… |
| Borderline LLM review | Duyệt LLM vùng biên | Chỉ gọi LLM khi điểm tương đồng mơ hồ |
| FastAPI | FastAPI | Khung backend Python |
| React / Vite | React / Vite | Khung giao diện web |
| PostgreSQL | PostgreSQL | CSDL quan hệ: quy tắc, chat, audit |
| Redis | Redis | Bộ nhớ đệm nhanh (cache) |
| Docker / Docker Compose | Docker / Compose | Chạy nhiều dịch vụ bằng container |
| Nginx | Nginx | Proxy ngược, phục vụ UI + chuyển API |
| Ollama | Ollama | Chạy LLM/embedding cục bộ |
| LocalStack / S3 | LocalStack / S3 | Lưu file thô và artifact (giống S3) |
| JWT | JWT (token đăng nhập) | Xác thực người dùng |
| RBAC | Phân quyền theo vai trò | Bác sĩ / clinical lead / admin |
| TLS | Mã hóa đường truyền | HTTPS bảo vệ dữ liệu trên mạng |
| SSE (Server-Sent Events) | Sự kiện đẩy từ server | Server gửi dần draft, card, câu trả lời |
| Endpoint / API | Điểm cuối / API | Đường gọi dịch vụ backend |
| Latency | Độ trễ / thời gian phản hồi | Thời gian từ hỏi đến có kết quả |
| Throughput | Thông lượng | Số yêu cầu xử lý trong một khoảng thời gian |
| Cache / TTL | Bộ nhớ đệm / thời gian sống | Lưu tạm để nhanh hơn; hết hạn thì xóa |
| Health / Liveness / Readiness | Kiểm tra sức khỏe / sống / sẵn sàng | Probe vận hành hệ thống |
| Bootstrap | Khởi tạo lúc chạy | Nạp catalog/index khi backend start |

## G. Đánh giá và chỉ số

| English | Tiếng Việt | Giải thích ngắn |
|---------|------------|-----------------|
| Accuracy | Độ chính xác | Tỷ lệ khuyến nghị đúng theo chuyên gia |
| Precision | Độ chính xác dương | Trong các cảnh báo “có”, bao nhiêu là đúng |
| Recall / Sensitivity | Độ nhạy / độ phủ | Bắt được bao nhiêu ca thật sự nguy hiểm |
| Specificity | Độ đặc hiệu | Đúng loại bỏ ca không có vấn đề |
| F1 score | Điểm F1 | Trung hòa precision và recall |
| PPV / NPV | Giá trị tiên đoán dương / âm | Xác suất đúng khi hệ thống bảo “có/không” |
| False positive / False negative | Dương tính giả / Âm tính giả | Cảnh báo oan / bỏ sót nguy hiểm |
| Latency P50 / P95 | Phân vị 50 / 95 thời gian đáp ứng | Trung vị và đuôi chậm |
| User satisfaction | Mức hài lòng người dùng | Điểm khảo sát bác sĩ |
| Ablation | Phân tích loại bỏ thành phần | Tắt từng phần để xem đóng góp |
| Threats to validity | Đe dọa tính hợp lệ | Giới hạn khi suy diễn kết quả |
| Baseline | Mốc so sánh | Hệ đối chứng để so hiệu quả |

## H. Cụm từ thiết kế quan trọng trong luận văn

| English (cụm) | Tiếng Việt gợi ý | Ý nghĩa trong hệ thống |
|---------------|-----------------|------------------------|
| Authority separation | Tách quyền quyết định | Rule quyết định an toàn; LLM chỉ giải thích |
| Safety before prose | An toàn trước văn bản | Card/cảnh báo hiện trước đoạn chat |
| Governed catalogs | Catalog được quản trị | Quy tắc phải được duyệt mới chạy |
| On-premise inference | Suy luận tại chỗ | Chạy LLM trong viện, hạn chế đưa dữ liệu ra cloud |
| Structured recommendation object | Đối tượng khuyến nghị có cấu trúc | JSON trạng thái từng nhóm thuốc (nguồn sự thật) |
| Evidence-grounded explanation | Giải thích bám bằng chứng | Câu trả lời dựa đoạn đã truy xuất |
| Cost-aware three-tier filter | Lọc 3 tầng tiết kiệm chi phí | Keyword → embedding → LLM vùng biên |
| Fork-join (GraphRAG ∥ reasoning) | Song song rồi hội tụ | Tìm bằng chứng song song với máy suy luận |
